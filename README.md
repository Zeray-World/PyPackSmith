## 一个很常见的处境

你电脑里躺着一堆 Python 小脚本：批量改文件名、合并 Excel、拆分 PDF、定时抓点数据、给图片加水印……每个都只有一两百行，每个你都想“双击就能用”。

但真到用的时候，三条路都不顺：

- **打开 IDE 跑？** 为了跑一个两百行的脚本，吃掉几百 MB 内存，等它启动十几秒，跑完还得记得关掉。
- **直接双击 `.py`？** 一个黑窗口糊在屏幕上，脚本跑完还停在 `Press any key`，发给同事更难看——“你这什么东西，一闪一闪的”。
- **打成 exe？** 每个 30 MB 起步。十个脚本就是 300 MB，二十个就是 600 MB，全塞在桌面或者 U 盘里。更烦的是改一行代码，还得等一分钟重新打包。

这个项目里的**轻量启动器**就是为这个处境做的：每个脚本编成一个 **~15 KB** 的 exe，双击就运行，**没有黑窗口**，可以钉到任务栏、发送到桌面、塞进右键菜单，跟一个原生小工具没区别。

体积小到你可以给**每一个**脚本都做一个。

## 它能做什么

选一个入口脚本（或一整个项目目录），选一种模式，点「开始打包」。

| 模式 | 产物 | 体积 | 目标机要求 | 适合 |
|---|---|---|---|---|
| **1 单文件** | 一个 `.exe` | 10–40 MB | 无 | 交给任何人，最稳 |
| **2 目录模式** | 一个 `.exe`（内含整个项目） | 10–60 MB | 无 | 有图片/配置/子模块的项目 |
| **3 文件夹模式** | 一个文件夹（onedir） | 同上，不压缩 | 无 | 启动最快，方便换配置 |
| **4 .spec** | 按已有施工图打 | 取决于 spec | 无 | 已有手工调好的 spec |
| **5 ⭐ 轻量启动器** | 一个 `.exe` | **~15 KB** | 需已装 Python 3 + 依赖库 | 自己用 / 同事 / 内网 / 一堆小脚本 |

界面上是五个单选，选完自动把不相关的参数置灰——不会让你勾出一组互相打架的选项。

## ⭐ 重点说：轻量启动器（~15 KB）

别的打包工具只做上表前四行。这一行是它没有的。

```
轻量启动器      ▏  ~15 KB
完整打包        ████████████████████████████████████████████   10 – 40 MB
                └── 差距约 2000 倍，且不随你 import 多少库而变化
```

**你往脚本里加 `import numpy`，轻量模式的 exe 体积不变**——因为 numpy 本来就不在包里，它在目标机上。

### 它到底做了什么

```
你的脚本.py  ──┐
图标 / 数据文件 ─┴─→  内嵌为 .NET 资源
                        │
                        ├─ 用 Windows 自带的 C# 编译器现场编译
                        │  %WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe
                        │  （Win10/11 随 .NET Framework 4.x 一起来，通常无需另装）
                        ↓
                    ~15 KB 的 .exe
                        │
双击 ───────────────────┘
  │
  ├─ 1. 把内嵌脚本解到 %LOCALAPPDATA%\<名字>_lite\<内容hash>\
  │       内容没变就复用，不会每次启动重解
  ├─ 2. 找本机的 Python，顺序是：
  │       PYPACKER_PYTHON 环境变量 → 构建时用的那个解释器
  │       → 注册表 PythonCore → PATH → 常见安装目录
  ├─ 3. pythonw.exe 无窗执行（控制台模式则用 python.exe）
  └─ 4. 出问题弹中文窗口，把原因和解决办法写给你
```

看不到命令行一闪而过，是因为无窗模式下引导器直接编成 `winexe` 子系统（控制台模式则编成 `exe`）——它根本没有窗口可以闪，不是“弹出来再快速隐藏”的假象。

### 为什么能小到 15 KB

PyInstaller 那 30 多 MB 里，绝大部分是 `python3xx.dll`、标准库 `base_library.zip`、`tcl/tk`、`VCRUNTIME140.dll`。这些东西目标机的 Python 安装目录里全都有，再塞一份进 exe 属于重复携带。

轻量模式只做一件事：**把“双击”翻译成“用哪个解释器跑哪个脚本”**。翻译这件事，一个 15 KB 的引导器就够了。

### 它会把错误说清楚，而不是闪一下就没

这是手写 stub 和新手打包器最容易漏的地方。引导器的失败路径全部做了人话处理：

| 情况 | 你看到的 |
|---|---|
| 目标机根本没装 Python | 弹窗说明需要 Python 3，并给出下载地址 |
| 装了但不是 3.x | 指出找到的版本号，提示不兼容 |
| 脚本报 `No module named requests` | 弹窗直接给出 `pip install requests` 命令 |
| 脚本自己有语法/导入错误 | 显示异常摘要和脚本路径，不用再去猜 |
| 本机没有 csc.exe | **构建时**就拦下来，说明原因，不会产出一个坏 exe |

### 它是可以删掉的功能

`light_stub.py` 是独立文件，和主程序之间只有“可选导入”这一条弱连接：

```python
try:
    import light_stub
except ImportError:
    light_stub = None   # 模式5 显示「不可用」，其余四个模式完全正常
```

反过来，`light_stub.py` 不 import 主程序里的任何东西，接口就三个：

```python
available()  -> (bool, 说明文字)      # 本机能不能编（csc 在不在）
build(...)   -> (exe 路径 | None, 错误 | None)
guess_name() -> 'xxx-需PY'
```

把这个文件删掉、改名、或单独放，主程序照常启动，只是模式 5 会显示「不可用」并说明原因。你只想用轻量功能的话，把 `light_stub.py` 拿走配个十行脚本也能用。

### 名字带后缀，防止发错文件

输出名留空时自动生成 `脚本名-需PY.exe`，自己填了就用你填的。同一个目录下两个版本并存，一眼分清哪个能发给陌生人。

### 什么时候别用它

- **发给完全不懂电脑的人** → 用模式 1。省下的 30 MB 换不来一次远程排障；
- **目标机是 Win7 且没装 .NET Framework 4** → 引导器起不来，换完整打包；
- **杀软很敏感** → 自己编的小 exe 偶尔被误报，加白名单即可（完整打包的 onefile 自解压同样会被误报，别以为换个模式就免疫）；
- **要带整个项目目录** → 不支持。整个目录嵌进去体积就回到 MB 级，和“省空间”自相矛盾，请用模式 2。

### 这条路用不上的参数会被置灰

不是藏起来让你找不到，是显示但禁用，并写明原因：

```
--onefile / --onedir   这里没有 Python 可打，形态固定是单文件
--hidden-import        模块由目标机的 Python 自己解析
--exclude-module       同上
--upx-dir / --splash   没有可压缩的运行时
--debug / --clean      没有 PyInstaller 缓存
```

轻量模式自己的参数只有两个：**隐藏黑窗口**、**请求管理员权限（UAC）**。

## 完整打包也不含糊

需要自包含的时候，还是得 PyInstaller。这部分不是简单套壳。

### 依赖分析是 AST，不是字符串匹配

大多数“自动检测依赖”的实现是在源码里搜模块名。后果很直接：注释里写一句 `# 以前用过 numpy`，numpy 就被打进包里。

这里把源码解析成语法树，只认真正的导入语句：

```python
import a.b.c                      # → a, a.b, a.b.c
from x import y, z                # → x, x.y, x.z
from . import sibling             # → 项目内部导入，不算第三方依赖
__import__("numpy")               # → numpy
importlib.import_module("pandas") # → pandas
importlib.util.find_spec("cv2")   # → cv2
```

然后拿**你选中的那个解释器**逐个 `find_spec`，分成四类：第三方 / 标准库 / 项目内部 / **解释器里根本没有**。

最后一类会标红——这才是 exe 一启动就崩的真正原因（尤其用 embeddable Python 打包时，那个发行版连 `site-packages` 都没有）。

> 实测：一个只在注释里提到 numpy / cv2 的脚本，字符串匹配方案打出 **137 MB**，改用 AST 后只保留真实依赖。

### 三种策略，而不是一个开关

- **自动** — 检测到的全部 `--hidden-import` 进去，最稳，体积换安心；
- **手动** — 弹清单自己勾，想瘦身或排除干扰时用；
- **不打包** — 交给 PyInstaller 自己分析。本机一定能跑，换台电脑极大概率 `ModuleNotFoundError`。

选“不打包”时界面会明确告诉你这个风险，而不是让你事后猜。

### 目录模式：整个项目 → 单个 exe

选「项目目录 + 入口脚本」，工具会：

- 把目录里除 `__pycache__` / `build` / `dist` / `venv` / `.git` 之外的文件**按原相对路径**打进去（不是全拍到根目录——那样包内结构会被拍平，代码里的相对路径全废）；
- 以入口脚本为程序入口，双击 exe 等于运行它；
- 自动注入运行时钩子把工作目录切到资源目录，让 `open("config.json")` 这类写法不失效；
- 打包时排除上一次的产物目录——否则第二次打包会把上次的 exe 又吞进去，越打越大。

> 别和「文件夹模式（onedir）」搞混：那个输出一个**文件夹**，exe 和依赖并排，启动更快，但要整个拷走。

### 解释器可以换

默认用运行本工具的那个 Python；也可一键扫描本机所有 Python 变成下拉列表，或手动浏览任意解释器（含 embeddable）。选到嵌入式版本时，下方常驻一行小字提醒它缺库的风险。

### 打包失败能查

- 实时构建日志（保留最近 800 行），可复制；
- 取消时用 `taskkill /T /F` 杀整棵进程树，不留孤儿进程继续占着文件；
- 内置故障对照表（见文末）；
- 配置逐字段读写，某一项损坏不会让整份设置归零（另存 `.bak`）。

## 快速开始

```text
1. 双击运行 PY脚本打包器.py（Python 3.8+，自带 tkinter 即可，无需 pip install）
2. 选入口 .py，或选「整个项目目录 + 入口脚本」
3. 选模式：想给小脚本做个双击图标 → 模式5；要发给陌生人 → 模式1
4. 确认解释器（默认就是启动本工具的那个）
5. 确认输出目录
6. 模块检测弹窗里选「自动」
7. 开始打包
```

产物出现在输出目录，名字取自脚本名；重名自动加 `(1)`、`(2)`，不覆盖你上一次的成果。

想把工具本身也做成免 Python 的 exe：选模式 1，把 `light_stub.py` 一起打包（会被自动识别为项目内模块）。

## 常见故障

**双击完全没反应 / 一闪就没**
先别勾 `--noconsole`，用控制台模式重打一次。空白的 GUI 程序什么都告诉你。

**`从服务器返回了一个参照`**
跟 PyInstaller 和你的代码都无关，是 Windows 拒绝启动这个 exe。唯一原因是清单里写了 `uiAccess="true"`（由 `--uac-uiaccess` 造成）。Windows 只允许「已数字签名 + 装在 Program Files 等受保护目录」的辅助功能程序用这个标志；未签名、又放在桌面的 exe 会被直接拒绝。本工具默认不写这个字段，需要管理员权限只勾 `--uac-admin` 就够。

**`ModuleNotFoundError: No module named xxx`**
完整打包：模块没打进包，回主页重新检测、选「自动」，并确认你选的那个解释器里确实装了这个库——缺的库在检测结果里是标红的。
轻量模式：这是**正常现象**，它不打包依赖，去目标机上 `pip install` 它提示的那个包。

**`FileNotFoundError: 某个图片/json`**
资源没打进去。用模式 2（目录模式），或勾上「运行时切到资源目录」。

**`Failed to execute script xxx`**
入口脚本本身有导入或语法错误。先在命令行 `python xxx.py` 跑一遍。

**杀软报毒**
onefile 的自解压行为容易被启发式引擎误判。换模式 3（onedir），或加白名单。

**用 embeddable Python 打包，exe 一启动就崩**
那个发行版没有 pip、没有 `Lib\site-packages`，第三方库根本没被分析到。稳妥做法是用标准安装的 Python 打包。

## 已知限制

- **仅 Windows**。轻量模式依赖 `csc.exe`；PyInstaller 部分本身跨平台，但 GUI 和路径处理只针对 Windows 验证过。
- **轻量模式的 exe 不自包含**，目标机必须有 Python 和对应依赖——这是它 15 KB 的全部原因，不是 bug。
- **`if TYPE_CHECKING:` 里的导入会被当成硬依赖**，可能多打一个包。可用「手动」策略剔除。
- **venv 只按目录名识别**（`venv` / `.venv` / `env`），自定义名字的虚拟环境在目录模式下可能被打进包。
- 依赖分析只看入口脚本和项目内可达的 `.py`，动态拼接的 `__import__(name)` 无法静态解析。
- 单文件模式每次启动都把内容解到 `%TEMP%\_MEI*`，正常退出自删；被强杀会残留，需手动清（或勾「清理缓存」）。轻量模式解在 `%LOCALAPPDATA%`，按内容 hash 复用，没有这个问题。
